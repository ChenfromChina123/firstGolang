## 后续修复（2026-07-07 晚）
用户反馈"看不到下移的文件或者文件夹选项，感觉只在顶部栏显示"。

**根因**：`.panel { overflow: hidden; }`（style.css 行 166）用于实现圆角效果，
但上传按钮区域 `<section class="panel upload-panel">` 继承了 overflow:hidden，
导致悬停展开的 `.upload-menu`（position:absolute, top:100%）被父级 panel 裁剪。

**修复**（style.css 行 258-260，最小侵入式）：
```css
/* 允许下拉菜单溢出 .panel 的 overflow:hidden */
.upload-panel { overflow: visible; }
.upload-panel .panel-head { overflow: visible; }
```
仅给 `.upload-panel` 单独 overflow:visible，不影响其他 panel 的圆角裁切效果。

## 后续修复（2026-07-07 晚 - z-index 层级）
用户反馈"被下方的文件列表的UI组件遮挡"——下拉菜单显示后又被文件库面板覆盖。

**根因**：`.upload-panel` 与 `.files-panel` 是兄弟元素，均无 z-index（默认 auto）。
按 CSS 绘制顺序，后置兄弟元素 `.files-panel` 会覆盖前置元素 `.upload-panel` 的可见溢出内容。
即使 `.upload-menu { z-index: 100 }`，也只在其所在层叠上下文内生效，无法跨越层叠上下文
对抗 `.files-panel`。

**修复**（style.css 行 258-260）：
```css
.upload-panel { overflow: visible; position: relative; z-index: 20; }
```
为 `.upload-panel` 创建独立层叠上下文（z-index:20 > 默认 auto），让整个上传面板及其溢出
内容（含下拉菜单）都绘制在 `.files-panel` 上方。其他 panel（files-panel 等）保持默认。

**版本号 bump**：`?v=20260707c` → `?v=20260707d`，强制浏览器重新加载 CSS。

**部署**：minify 后通过 SFTP 上传 dist/style.css、dist/index.html、dist/app.js
到生产服务器 `/opt/filesync/web/`。

**Playwright 验证结果**（悬停 "+ 上传 ▾" 按钮后）：

[web/app.js:259-261](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/web/app.js#L259-L261)：
```js
getUploadFilename() {
    const relativePath = this.file.webkitRelativePath || this.file.name;
    return this.targetDir ? this.targetDir + relativePath : relativePath;
}
```
- 普通文件 webkitRelativePath 为空，回退 file.name（行为不变）
- 文件夹文件 webkitRelativePath 含相对路径（如 "subdir/file.txt"），保留目录结构
