# FileSync 安全加固实施计划

## 上下文（Context）

基于 [doc/aistudy.icu 安全评估报告.md](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/doc/aistudy.icu%20安全评估报告.md) 的发现，aistudy.icu 整体安全评分 7.3/10，存在多项中低风险问题需要加固。本计划聚焦于代码层面可实施的修复，按报告优先级分阶段实施。

**架构关键事实**（基于代码探索）：
- 项目为单一 Go 二进制，**没有独立 Nginx**——所有 HTTP 处理（TLS、安全头、限流、路由）都在 Go 内
- HTTPS 通过 `autocert` 自动申请 Let's Encrypt 证书（main.go:414-418）
- 中间件链：`SecurityHeaders -> RefererCheck -> JWT -> mux`（main.go:346-347）
- 限流使用 `golang.org/x/time/rate`（令牌桶），**内存实现**，不依赖 Redis
- ShareHandler 已有 `downloadLimiter`（10/min/IP）用于下载端点，但 `/api/s/{id}` 获取分享信息端点无限流

## 当前状态分析（已通过 Read 工具验证）

- ✅ `internal/middleware/security.go`：设置 `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Content-Security-Policy: frame-ancestors 'self'`

- ✅ `internal/middleware/referer.go`：防盗链中间件，白名单精确匹配

## 实施内容（按优先级分阶段）

### 阶段一：高优先级（中风险问题）

#### 改动 1：完善安全响应头中间件

**文件**：[internal/middleware/security.go](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/internal/middleware/security.go)

**当前代码**（仅 4 个 header）：
```go
func SecurityHeaders(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("X-Frame-Options", "SAMEORIGIN")
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("Referrer-Policy", "strict-origin-when-cross-origin")
        w.Header().Set("Content-Security-Policy", "frame-ancestors 'self'")
        next.ServeHTTP(w, r)
    })
}
```

**改动内容**：扩展为 8 个安全头
- 新增 `Strict-Transport-Security: max-age=31536000; includeSubDomains`（HSTS，仅 HTTPS 模式下发，通过参数控制）
- 完善 CSP：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'self'; base-uri 'self'; form-action 'self'`
  - `style-src 'unsafe-inline'`：因为前端有内联 `<style>` 和 SVG 内联样式
  - `img-src data: blob:`：缩略图使用 data URL 和 blob URL
  - `font-src data:`：Google Fonts 字体
  - `connect-src 'self'`：fetch/XHR 仅同源
- 新增 `Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()`
- 新增 `X-Permitted-Cross-Domain-Policies: none`（防止 Adobe PDF/XLSX 嵌入）
- 新增 `X-XSS-Protection: 1; mode=block`（兼容旧浏览器，现代浏览器已废弃但不冲突）

**签名变更**：`SecurityHeaders` 需要参数化以支持 HTTPS 模式判断：
```go
func SecurityHeaders(enableHSTS bool, next http.Handler) http.Handler
```

**main.go 调用处调整**（main.go:347）：
```go
finalHandler := middleware.SecurityHeaders(enableHTTPS, referered)
```

#### 改动 3：验证登录限流配置

**文件**：[cmd/server/main.go:224](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/cmd/server/main.go#L224)

**当前配置**：`auth.NewLoginRateLimiter(0.083, 5)` —— rps=0.083（即 5/分钟），burst=5

**问题分析**：报告说"连续 10 次错误登录全部返回 401 未触发 429"。原因：burst=5 + rps=0.083*60=5/分钟 = 总共允许 10 次/分钟。所以 10 次正好打满但不超限。

**改动内容**：调整限流参数更严格
- 选项 A：保持 rps=0.083，burst 降为 3（共 8 次/分钟）
- 选项 B：rps 降为 0.05（3/分钟），burst=3（共 6 次/分钟）

**推荐**：选项 A（轻度收紧，不影响正常用户）。修改 main.go:224：
```go
loginLimiter := auth.NewLoginRateLimiter(0.083, 3) // 5次/分钟/IP, burst=3
```

### 阶段二：中优先级（低风险问题）

#### 改动 4：HTTP 方法限制中间件

**文件**：新建 `internal/middleware/methodguard.go`

**问题**：`/api/health` 接受所有 HTTP 方法（TRACE、CONNECT 等）。虽然未发现 XST 漏洞，但应禁用非标准方法。

**改动内容**：创建方法限制中间件
```go
package middleware

import "net/http"

// MethodGuard 拒绝 TRACE、CONNECT 方法的请求，防止 XST 攻击和潜在的方法滥用。
// 其他标准方法（GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS）放行由各 handler 自行处理。
func MethodGuard(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        switch r.Method {
        case http.MethodTrace, http.MethodConnect:
            http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
            return
        }
        next.ServeHTTP(w, r)
    })
}
```

**main.go 集成**（main.go:346-347 调整中间件链）：
```go
referered := middleware.RefererCheck(allowedDomains, jwtAuthed)
secured := middleware.MethodGuard(referered)
finalHandler := middleware.SecurityHeaders(enableHTTPS, secured)
```

中间件链变为：`SecurityHeaders -> MethodGuard -> RefererCheck -> JWT -> mux`

## 假设与决策

### 假设
1. 生产服务器 `filesync.service` 当前运行的是 `filesync_server_linux` 二进制（部署后需重新编译并上传）
2. 项目使用 Go modules（`go.mod` 已存在）
3. `golang.org/x/time/rate` 已在 `go.mod` 中（ratelimit.go 已 import）
4. 浏览器对 `unsafe-inline` 的 CSP 兼容性已确认（前端有内联样式）

### 决策
1. **HSTS 仅在 HTTPS 模式下发送**：避免开发环境（HTTP）误锁死。通过 `enableHTTPS` 参数控制。
2. **CSP 允许 `style-src 'unsafe-inline'`**：因为前端 style.css 有内联 SVG 样式和动态 style 属性。完全去掉 unsafe-inline 会破坏 UI。这是实用性与安全性的权衡。
3. **share info 限流设为 60 次/分钟**：正常用户访问分享链接不会超过 60 次/分钟，但暴力枚举 8 位 hex（16^8=43 亿）需要远超此速率才有意义，60/min 足够阻拦。
4. **登录限流参数收紧**：从 `(0.083, 5)` 改为 `(0.083, 3)`，将 10 次/分钟降为 8 次/分钟，正常用户输入密码 3 次足够，攻击者阻拦更早。
5. **HTTP 方法限制放在最外层**：MethodGuard 在 SecurityHeaders 之后、RefererCheck 之前，避免 TRACE 请求触发不必要的 Referer 检查。
6. **路径规范化不改动**：Go ServeMux 已正确处理，无实际漏洞。
7. **security.txt 放在 web/.well-known/**：Go 的 FileServer 自动服务，无需改路由。

## 风险与回滚

### 风险
1. **CSP 过严导致前端功能异常**：通过允许 `style-src 'unsafe-inline'` 和 `img-src data: blob:` 缓解。部署后用 Playwright 验证所有页面功能。
2. **HSTS 锁死**：仅在 HTTPS 模式下发，且 `max-age=31536000`（1 年）。如果证书出问题，用户无法访问。可通过降低 max-age 到 300 秒（5 分钟）测试期缓解，确认稳定后再升到 1 年。
3. **限流误伤正常用户**：share info 60/min 足够高，登录 8/min 也足够。监控日志确认无误伤。

### 回滚方案
- 每个改动单独 commit，出问题可单独 revert
- 编译失败立即回滚到上一个稳定版本
- CSP 引起 UI 异常：临时移除 CSP 或回退到 `frame-ancestors 'self'`
- HSTS 引起访问问题：注释掉 HSTS 行重新部署
