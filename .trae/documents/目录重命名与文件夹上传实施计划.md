# 目录重命名与文件夹上传实施计划

## Context

用户提出两个新需求：
1. **目录重命名功能**：当前只能通过"移动目录"间接重命名目录，UX 不直观
2. **文件夹上传功能**：完全未实现，用户希望"优化的很好"——保留目录结构、批量并发、良好的冲突体验

**核心发现（关键洞察）**：
- 后端**零改动**即可支持两个功能：
  - `MoveDir` API（[file.go:392-470](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/internal/handler/file.go#L392-L470)）批量更新目录前缀，本质就是"目录重命名"
  - `validateFilePath`（[upload.go:823](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/internal/handler/upload.go#L823)）已允许 `path/to/file` 多级路径格式，文件夹上传的 filename 就是多级路径
- 现有上传链路已具备：3 文件并发（`MAX_PARALLEL_FILES=3`）、`globalStrategy` 批量冲突决策、单文件独立进度条、失败隔离
- 全部改动集中在前端 `web/app.js` 和 `web/index.html`

## 实施顺序

**先做文件夹上传**（全新功能，价值高），**再做目录重命名**（UI 文案微调，改动小）。

### 复用现有机制（无需新写）
- **并发控制**：`MAX_PARALLEL_FILES=3` 文件级并发（[app.js:2899](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/web/app.js#L2899)）+ 用户配置的 chunk 并发（默认 5）= 总并发 15
- **冲突处理**：`askConflict` + `globalStrategy`（[app.js:541-557](file:///d:/STUDY/GO/StudyGolang/firstGolang/filesync/web/app.js#L541-L557)），用户勾选"应用到后续所有冲突"一次决策批量处理 1000+ 文件
- **进度展示**：每个文件独立 task 进度条（已有逻辑）
- **失败隔离**：task.run 内部 try-catch（已有逻辑）

### 边界处理
- **空文件夹**：webkitdirectory API 不会返回空目录，不创建 .keep 占位（避免复杂度，可接受）
- **超长路径**：依赖后端 validateFilePath 校验，前端不重复实现
- **同名目录已存在**：后端 InitUpload 的冲突检查会返回 409，前端走现有 conflict 流程

## 验证步骤

### 文件夹上传验证
1. 本地启动 server（`go run ./cmd/server`）
2. 浏览器访问 http://localhost:8080/web/
3. 点击"+ 上传文件夹"按钮，选择一个含多级子目录的文件夹
4. 验证：
   - 文件列表按原目录结构展示（如 `sub1/sub2/file.txt`）
   - 进度条按文件逐个推进
   - 故意选含同名文件的文件夹，验证 globalStrategy 批量决策生效
   - 上传完成后刷新页面，文件结构保留
5. 验证后端零改动：直接走现有 `/api/upload/init`、`/api/upload/chunk`、`/api/upload/complete`

### 目录重命名验证
1. 创建目录 `test/`，里面放几个文件
2. 选中 `test/` 目录，验证工具栏按钮文案为"重命名目录"
3. 点击按钮，modal 标题为"重命名目录"，输入框默认选中末级目录名
4. 修改末级目录名，确认后验证：
   - 列表中目录名变化
   - 目录下所有文件的 filename 前缀更新
   - 数据库 owner 字段未丢失
5. 右键菜单验证：单选目录时菜单项为"重命名目录"

### 部署步骤
1. 本地验证通过后，运行 `node tools/minify/minify.js` 同步 dist 产物
2. 提交 git：`git add web/app.js web/index.html web/dist/ && git commit -m "feat: 新增文件夹上传功能 + 优化目录重命名 UI"`
3. 部署到生产：上传 `web/dist/` 到 `/opt/filesync/web/dist/`
4. 生产环境验证
