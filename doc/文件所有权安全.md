# 文件所有权安全模块

## 概述

FileSync 文件所有权安全模块实现用户间的文件隔离，确保用户只能操作自己上传的文件，admin 可操作所有文件，分享链接公开访问按创建者过滤防止越权下载。

## 数据模型

### files 表 owner 字段

```sql
ALTER TABLE files ADD COLUMN owner VARCHAR(64) NOT NULL DEFAULT '';
CREATE INDEX idx_files_owner ON files(owner);
```

- **类型**：VARCHAR(64) / TEXT
- **默认值**：空字符串（历史数据）
- **含义**：文件归属用户名（非 user ID），与 `shares.created_by` 一致
- **索引**：`idx_files_owner` 支持按 owner 快速过滤

### 增量迁移

`migrateFilesAddOwner()` 函数检测 files 表是否缺少 owner 列，缺少则执行 `ALTER TABLE ADD COLUMN`。兼容 MySQL 和 SQLite 两种 dialect。

## 权限规则

| 角色 | 可见文件范围 | 可操作文件 |
|------|-------------|-----------|
| admin | 所有文件（owner="" + 所有用户文件） | 下载/删除/重命名/移动/分享任何文件 |
| 普通用户 | 仅 owner=自己用户名 的文件 | 下载/删除/重命名/移动/分享自己的文件 |
| 未登录 | 无 | 401 Unauthorized |
| 分享访客 | 分享的文件/目录 | 仅下载，按 shares.created_by 过滤 |

### 历史文件处理

- 历史文件 owner="" 仅 admin 可操作
- 可选：执行 `UPDATE files SET owner='admin' WHERE owner=''` 将历史文件归给 admin

## API 权限校验

### 上传（upload.go）

| API | 权限逻辑 |
|-----|---------|
| POST /api/upload/init | 冲突检查按 owner 过滤（用户 A/B 可上传同名文件） |
| POST /api/upload/complete | fileRecord.Owner = auth.UsernameFromContext(ctx) |

### 文件管理（file.go）

| API | 权限逻辑 |
|-----|---------|
| GET /api/files | ListFiles(prefix, owner) — admin 传 ""，普通用户传 username |
| GET /api/files/{id} | GetFile 后校验 f.Owner != username && role != "admin" → 403 |
| DELETE /api/files/{id} | GetFile 后校验所有权 → 403 |
| DELETE /api/files?prefix= | DeleteFilesByPrefix(prefix, owner) — 按 owner 过滤 |
| POST /api/files/mkdir | FileRecord.Owner = username；冲突检查按 owner 过滤 |
| POST /api/files/rename | GetFile 后校验所有权；FindFileByName(newFilename, username) 冲突检查 |
| POST /api/files/move-dir | ListFiles 传 owner 过滤；UpdateFilename 传 owner |
| POST /api/files/batch-delete | 逐个 GetFile 校验所有权，非 owner 跳过并计入失败 |

### 下载（download.go）

| API | 权限逻辑 |
|-----|---------|
| GET /api/download/{id} | GetFile 后校验 f.Owner != username && role != "admin" → 403 |
| GET /api/download/dir?prefix= | ListFiles(prefix, owner) — admin 传 ""，普通用户传 username |

### 分享（share.go）

| API | 权限逻辑 |
|-----|---------|
| POST /api/share (file) | GetFile 后校验 f.Owner != username && role != "admin" → 403 |
| POST /api/share (dir) | ListFiles(dirPrefix, owner) 按当前用户过滤，空目录返回 404 |
| DELETE /api/share/{id} | 校验 s.CreatedBy != username → 403 |
| GET /api/s/{id} (公开) | 目录分享 ListFiles(s.DirPrefix, s.CreatedBy) 按创建者过滤 |
| GET /api/s/{id}/download (公开) | 目录分享 ListFiles(s.DirPrefix, s.CreatedBy) 按创建者过滤 |

> **安全增强**：分享公开访问按 `shares.created_by` 过滤，防止同 prefix 下其他用户文件被公开下载。

## 错误处理

| HTTP 状态码 | 场景 | 理由 |
|------------|------|------|
| 401 Unauthorized | 未登录访问受保护 API | 需要登录 |
| 403 Forbidden | 文件存在但无权访问 | 文件 ID 不可枚举（128 位随机 hex） |
| 404 Not Found | 文件不存在 | 真实不存在 |

## 关键设计决策

1. **owner = 用户名**（非 user ID）：与现有 `shares.created_by` 一致，可读性好，便于调试
2. **admin 可操作所有文件**：便于管理，admin role 从 JWT claims 获取
3. **历史文件 owner 为空**：仅 admin 可操作，避免数据丢失
4. **冲突检查按用户隔离**：用户 A/B 可上传同名文件，互不干扰
5. **分享链接公开访问**：/api/s/{id}/download 不受 owner 限制，但按 shares.created_by 过滤
6. **UploadSession 不存储 owner**：CompleteUpload 直接从 context 获取 username，无需冗余存储（session 生命周期短）
7. **inline 校验逻辑**：不提取 canAccessFile 辅助函数，`f.Owner != username && role != "admin"` 更直观

## 验证标准

| 验证项 | 预期结果 |
|--------|----------|
| 用户 A 上传文件 | files.owner = "userA" |
| 用户 A 下载自己的文件 | 200 |
| 用户 A 文件列表 | 只看到自己的文件 |
| 用户 A 删除自己的文件 | 200 |
| 用户 A 创建自己文件的分享 | 200 |
| 分享链接公开下载 | 200（无需认证） |
| admin 文件列表 | 看到所有文件 |
| admin 下载任何文件 | 200 |
| 用户 B 下载 A 的文件 | 403 Forbidden |
| 用户 B 删除 A 的文件 | 403 |
| 用户 B 创建 A 的文件分享 | 403 |
| 历史文件（owner 空）普通用户访问 | 403 |
| 历史文件 admin 访问 | 200 |
