# 分享链接功能与跨浏览器配置同步

## 一、功能概述

### 1.1 跨浏览器配置同步
用户在 Web 控制台修改的分片大小和并发数，原来仅存储在浏览器 localStorage，换浏览器/设备后丢失。现改为服务器端持久化，登录后自动加载个人配置。

**策略**：localStorage 即时响应 + 服务器后台异步同步。两者双写，localStorage 保证 UI 即时反馈，服务器保证跨浏览器一致性。

### 1.2 分享链接功能
用户可将文件或目录生成分享链接，访客无需登录即可查看和下载。

**特性**：
- 支持文件和目录两种分享类型（目录下载时打包为 ZIP）
- 有效期可选：永久 / 7 天 / 30 天
- 下载次数去重：同一访客重复下载不增加计数（visitor cookie + 数据库 UNIQUE 约束）
- 独立分享页面：`/web/share.html?id=xxx`，简洁界面，无侧边栏和上传功能

## 二、数据库表设计

### 2.1 shares 表 — 分享记录

```sql
CREATE TABLE shares (
    id              VARCHAR(32) PRIMARY KEY,     -- 8 字符短 ID（16 字节随机 hex 前 8 位）
    file_id         VARCHAR(32),                 -- 分享文件的 ID（文件分享时填）
    dir_prefix      VARCHAR(1024),               -- 分享目录的前缀（目录分享时填，如 "docs/"）
    share_type      VARCHAR(8) NOT NULL,         -- "file" 或 "dir"
    created_by      VARCHAR(64) NOT NULL,        -- 创建者用户名
    created_at      DATETIME NOT NULL,           -- 创建时间
    expires_at      DATETIME,                    -- 过期时间（NULL 表示永久）
    download_count  INTEGER NOT NULL DEFAULT 0,  -- 累计下载次数（去重后）
    max_downloads   INTEGER,                     -- 最大下载次数（预留，当前未限制）
    is_active       BOOLEAN NOT NULL DEFAULT 1   -- 是否有效（删除时置 0）
);
```

### 2.2 share_downloads 表 — 下载记录（去重）

```sql
CREATE TABLE share_downloads (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    share_id      VARCHAR(32) NOT NULL,          -- 关联的分享 ID
    visitor_id    VARCHAR(64) NOT NULL,          -- 访客 cookie 值（32 字符 hex）
    ip            VARCHAR(45),                   -- 访客 IP（IPv4/IPv6）
    user_agent    VARCHAR(512),                  -- 访客 User-Agent
    downloaded_at DATETIME NOT NULL,             -- 下载时间
    UNIQUE(share_id, visitor_id)                 -- 关键：同一访客同一分享只记录一次
);
```

**去重原理**：`UNIQUE(share_id, visitor_id)` 约束 + `INSERT IGNORE`（MySQL）/ `INSERT OR IGNORE`（SQLite）。首次插入成功时 `RowsAffected > 0`，才更新 `shares.download_count`；重复插入被忽略，计数不增加。

### 2.3 user_settings 表 — 用户配置

```sql
CREATE TABLE user_settings (
    username    VARCHAR(64) PRIMARY KEY,         -- 用户名（主键）
    chunk_size  INTEGER NOT NULL,                -- 分片大小（字节）
    concurrency INTEGER NOT NULL,                -- 并发数
    updated_at  DATETIME NOT NULL                -- 最后更新时间
);
```

## 三、API 接口说明

### 3.1 分享管理 API（需认证）

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/share` | 创建分享 |
| `GET` | `/api/share` | 列出当前用户的所有分享 |
| `DELETE` | `/api/share/{id}` | 删除分享（仅创建者可删） |

**创建分享请求体**：
```json
{
  "share_type": "file",          // "file" 或 "dir"
  "file_id": "abc123...",        // share_type=file 时必填
  "dir_prefix": "docs/",         // share_type=dir 时必填
  "expires_in": 604800           // 有效期秒数：0=永久, 604800=7天, 2592000=30天
}
```

**创建分享响应**：
```json
{
  "id": "xyz789ab",
  "share_type": "file",
  "url": "/web/share.html?id=xyz789ab"
}
```

### 3.2 分享公开访问 API（无需认证）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/s/{id}` | 获取分享公开信息（不含 file_id/storage_path 等敏感字段） |
| `GET` | `/api/s/{id}/download` | 下载文件或目录（目录打包为 ZIP） |

**公开信息响应（SharePublicInfo）**：
```json
{
  "id": "xyz789ab",
  "share_type": "file",
  "name": "report.pdf",
  "size": 1048576,
  "file_count": 0,               // 仅目录分享时有意义
  "expires_at": "2026-07-13T10:00:00Z",  // null 表示永久
  "download_count": 3,
  "is_expired": false
}
```

**状态码**：
- `200`：正常返回
- `404`：分享不存在或已删除
- `410`：分享已过期

### 3.3 配置同步 API（需认证）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/settings` | 获取用户配置（无记录时返回默认值 8MB/3） |
| `POST` | `/api/settings` | 保存用户配置 |

**保存请求体**：
```json
{
  "chunk_size": 1048576,   // 最小 1024
  "concurrency": 8         // 范围 1-16
}
```

## 四、前端页面说明

### 4.1 主控制台分享功能（index.html + app.js）

**分享按钮**：
- 文件库树形列表中，每个文件行和目录行右侧都有"分享"按钮
- 点击后弹出分享创建对话框

**分享创建对话框（#share-modal）**：
- 有效期选择：永久 / 7 天 / 30 天
- 创建后显示完整链接（`window.location.origin + data.url`）
- 复制按钮：一键复制链接到剪贴板

**分享管理对话框（#share-manage-modal）**：
- 列出当前用户创建的所有分享
- 每条显示：名称、类型（文件/目录）、状态（有效/过期）、创建时间、过期时间、下载次数
- 操作：复制链接、删除分享

### 4.2 独立分享页面（share.html + share.js）

**设计原则**：简洁页面，无侧边栏、无上传功能，仅展示分享内容信息 + 下载按钮。

**三态展示**：
1. **加载中**：旋转动画 + "正在加载分享内容…"
2. **错误状态**：红色感叹号图标 + 错误标题 + 错误描述
   - 链接无效（无 id 参数）
   - 分享不存在（404）
   - 分享已过期（410 或 is_expired=true）
   - 网络错误
3. **正常状态**：
   - 类型徽章（文件/目录）
   - 名称
   - 元信息网格：大小、文件数（仅目录）、下载次数、有效期至
   - 下载按钮
   - 提示文字："同一访客重复下载不会增加下载次数。"

**技术要点**：
- 使用原生 `fetch`（非 app.js 的 `apiFetch`），因为分享页面不涉及认证，不应触发 401 跳转登录页
- 下载按钮使用 `window.location.href` 跳转，由后端 `Content-Disposition` 触发文件保存对话框，避免 fetch 在内存中缓存整个文件

## 五、去重机制详解

### 5.1 visitor cookie

```
首次访问分享页面
   │
   ▼ 检查 cookie "visitor"
   │
   ├── 存在 → 使用现有 visitor_id
   │
   └── 不存在 → 生成 16 字节随机 hex（32 字符）
                设置 cookie：visitor=xxx; Path=/; MaxAge=30天; HttpOnly; SameSite=Lax
                跨所有分享复用同一 visitor_id
```

**设计决策**：
- `SameSite=Lax`：防止 CSRF，但允许顶级导航携带（点击分享链接时能带上）
- `HttpOnly`：防止 XSS 读取
- 30 天有效：合理期限，避免短期失效导致重复计数
- 跨所有分享复用：同一访客对不同分享的下载行为可关联分析（未来扩展）

### 5.2 数据库去重流程

```
访客点击下载按钮 → GET /api/s/{id}/download
   │
   ▼ 后端处理
   │
   ├── 1. 检查分享有效性（存在 + 未过期 + active）
   │
   ├── 2. 获取/设置 visitor cookie
   │
   ├── 3. INSERT IGNORE INTO share_downloads (share_id, visitor_id, ip, user_agent, downloaded_at)
   │      └── UNIQUE(share_id, visitor_id) 约束：
   │          ├── 首次插入成功 → RowsAffected = 1 → UPDATE shares SET download_count += 1
   │          └── 重复插入忽略 → RowsAffected = 0 → 不更新计数
   │
   └── 4. 流式传输文件内容（io.Copy 单文件 / zip.NewWriter 目录打包）
```

### 5.3 边界情况

| 场景 | 行为 |
|------|------|
| 清除 cookie 后再下载 | 计数 +1（新 visitor_id） |
| 换浏览器/设备下载 | 计数 +1（不同 visitor_id） |
| 同一浏览器无痕模式 | 计数 +1（无痕模式不共享 cookie） |
| 同一分享多次复制链接 | 不影响计数（仅下载时计数） |
| 分享过期后访问下载 | 返回 410，不计数 |

## 六、认证白名单配置

`/api/s/` 路径在认证中间件白名单中以 `/` 结尾，触发**前缀匹配**：

```go
// internal/auth/middleware.go
whitelist := []string{
    "/api/login",
    "/api/s/",      // 前缀匹配：/api/s/abc 和 /api/s/abc/download 都能公开访问
    "/web/",        // 前缀匹配：/web/share.html 无需认证
    // ...
}
```

**匹配规则**：
- 以 `/` 结尾的路径：前缀匹配（如 `/api/s/` 匹配 `/api/s/`、`/api/s/abc`、`/api/s/abc/download`）
- 不以 `/` 结尾的路径：精确匹配（如 `/api/login` 只匹配 `/api/login`）
